# 合作战场与布防修正

## 目标

合作备战在九路地图中显示各座位固定负责的三路：座位 0 为 1–3，座位 1 为 4–6，座位 2 为 7–9。每名玩家首回合即可在自己三路的九列布防。服务端继续用玩家自己的 0–2 路坐标结算，客户端在收发布防时映射本地与全局路号。其他玩家的路只作为背景显示，不允许误放。合作模式不显示单人第二、第三回合扩路提示。

合作布防点击或拖动建筑后先高亮拟放置的格子与建筑，显示建筑、路号、列号和金币花费；只有点击「确认放置」才扣金币、写入布防。取消、换卡、切回房间或备战锁定时清除待确认位置。单人教学与原有快速放置保持不变。

## 战斗呈现

继续以 Cloudflare Durable Object 的确定性结果为胜负和生命值唯一真源。共享结算器在本机重算时附加每个时间段、每条本地路的出怪与击杀数量，不传输战斗帧。客户端把全队建筑映射到九路，在现有 Canvas 战场上呈现建筑、僵尸、攻击和家园受击动画；HUD 显示玩家生命值与回合时间。动画按结算事件调度，最终结果仍使用服务端返回值。玩家界面只称“合作战斗”，不暴露内部播放机制。离开、切后台和回合结束时正确暂停或清除画面状态。

合作结算为每座建筑保存单人模式一致的基础耐久、升级倍率、形态耐久倍率和淬火钢加成。每路尸群会持续攻击离裂隙最近的存活建筑；建筑耐久归零后，尸群才转向后面的建筑。该路建筑全部摧毁后，僵尸才会攻击家园。尸群和建筑耐久都跨结算时间段保留，合作结果由服务器确定；客户端按结算轨迹播放建筑掉血、受击和倒塌过程，不传输战斗帧。全队家园同时失守时以该时间点结束本局。房主主动离开或心跳超时会结束房间；备战中超过 15 秒没有心跳的非房主使用服务器已保存的布防自动准备，若全员因此准备则立即开战。

## 实现步骤

1. 修正合作路号映射、可放区域与画布遮罩，去掉合作扩路文案。
2. 为合作布防增加待确认状态、位置预览和确认/取消控件。
3. 在本地结算轨迹添加逐路事件与单位受击表现；新建仅供绘制的合作战场，不运行单人 `Battle.update`。
4. 让主循环绘制合作战斗，改用现有战场画面和轻量战斗 HUD，移除覆盖画面的进度条。
5. 增加房主离开结束房间、离线成员自动准备和全队失守提前结算。
6. 将布防确认框锚定在待放置建筑附近。
7. 重新打包 H5/iOS；服务端共享结算器同步部署，确保新旧客户端结算兼容。
