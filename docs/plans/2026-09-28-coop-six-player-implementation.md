# 2–6 人合作实现计划

**目标：** 让合作房间支持 2–6 人，六人时左右两侧各有三名玩家，每名玩家负责自己一侧的三路。

**方案：** 座位 0–2 映射到左侧 `p`，座位 3–5 映射到右侧 `g`；侧内座位使用 `seat % 3` 映射三组路段。两边复用同一组九个纵向路坐标，各自从裂隙向本侧家园防守。Worker 保存仍使用原有 seat / 本地三路布防数据格式。

**交互：** 大厅最多六人；房主在 2–5 人时可随时开局，六人满员自动进入备战。这样三人到齐时不会提前锁房。

---

## 实施步骤

1. **共享座位映射与房间规则** — 更新客户端座位/侧别辅助逻辑、房间容量、自动开局和房主动态开局入口；房主并发开局与第六人加入仍由 Durable Object 顺序裁决。
2. **两侧布防** — 让右侧玩家用镜像网格放置、升级和拆除建筑；检查本地三路映射、放置预览、选中态、遮罩、HUD 侧别和职责文案。
3. **两侧战斗与家园** — 让确定性模拟把构筑、尸潮、受击、倒下停用和存活目标映射到对应的 `p`/`g` 家园；六座家园共同决定团队胜负，回放还原所有建筑和血条。
4. **房间服务和对外文案** — Worker 接受六名成员并在六人满房时开局；更新 H5/iOS 菜单、隐私页、上架文案和 Worker 文档的人数范围。
5. **打包与发布** — 重新生成 H5/iOS 同源产物，并准备合作 Worker 部署，使已发布客户端能使用六人房间。

## 完成条件

- 2–6 人都能创建/加入房间；第 3–5 人加入后大厅保持开放，房主可开始；第 6 人加入后自动开始。
- 座位 0–2 只在左侧区域布防，3–5 只在右侧区域布防；服务器结算和各客户端回放使用相同侧别、路线及家园状态。
- 页面、隐私说明和部署文档不再把合作人数写成 2–3。

初版实现时未执行自动化测试；随后按用户要求补跑了多客户端 E2E，结果见执行记录。
