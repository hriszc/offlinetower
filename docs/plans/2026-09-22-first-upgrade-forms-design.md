# 首次升级三选一形态设计

## 1. 目标与边界

目标：让每个防御建筑在第一次升级（Lv.1 → Lv.2）时从三个明确形态中选择一个，形成构筑分支；Lv.2 → Lv.3 仍沿用现有普通升级。

约束：

- 不改变建筑基础造价、升级费用公式和 12 小局节奏。
- 不新增美术资源；先用名称、图标、颜色、面板文案和少量战场特效表达形态。
- 形态必须能被当前纯逻辑模拟、镜像机器人和平衡工具读取。
- 选择失败、取消或备战结束时不得产生半升级状态。

## 2. 方案取舍

### 方案 A：单位数据挂 `form` 字段（推荐）

建筑对象从 `{type, col, lane, lv}` 扩展为 `{type, col, lane, lv, form}`。形态数据集中放在 `FORMS[type]`，战斗工厂按 `form` 叠加局部修正。

- 优点：保留现有单位类型和遗物系统，升级、回收、机器人构筑、平衡工具都能沿用同一条路径。
- 缺点：需要在 `makeUnit`、升级 UI、机器人升级和平衡工具各接入一次。

### 方案 B：把每个形态复制成新单位类型

例如 `barricade_iron`、`barricade_thorn`。

- 优点：战斗代码改动最少。
- 缺点：单位表、卡片、遗物条件和机器人权重会膨胀，后续平衡容易漏改。

### 方案 C：只做 UI 描述，不改变战斗数值

- 优点：实现最快。
- 缺点：三选一会变成没有后果的文案选择，不满足构筑分支目标。

采用方案 A。

## 3. 推荐数据结构

```js
var FORMS = {
  barricade: [
    {
      id: 'ironwall',
      name: '铁壁',
      icon: '▣',
      role: '耐久',
      desc: '把木板换成整面铁皮，单纯活得更久。',
      lv2: { hpMul: 1.28 },
      lv3: { hpMul: 1.45 },
      color: '#b9c2cc',
    },
  ],
};
```

单位对象示例：

```js
{ type: 'barricade', col: 3, lane: 0, lv: 2, form: 'ironwall' }
```

`lv2`、`lv3` 只描述形态自身的局部修正；建筑基础值、等级成长和全局遗物仍然先计算。无效 `form` 使用无修正的 neutral 形态，保证旧构筑或异常数据仍可运行。

## 4. 交互流程

1. 备战期点击 Lv.1 建筑，面板显示“首次升级 · 三选一”和当前升级费用。
2. 点击升级按钮打开三张形态卡片；此时不扣金币。
3. 卡片展示形态名、定位、Lv.2 效果、Lv.3 预览和费用。
4. 选择卡片后校验金币，扣费一次，写入 `lv=2` 和 `form`，刷新备战构筑。
5. 点击取消关闭选择，不扣费、不升级。
6. Lv.2 → Lv.3 不再弹出形态选择，沿用当前普通升级按钮。
7. 建筑回收仍按已支付的等级费用计算，不因形态额外收费。
8. 备战倒计时结束或开始防守时，若选择框仍打开，直接关闭且不扣费。

UI 复用现有 `#overlay`，新增 `overlayMode='form'`。三张卡片保持固定顺序，便于玩家学习和截图比较；不随机洗牌。

## 5. 六个建筑的十八个形态

下表中的倍率都是在“基础值 × 等级成长 × 全局遗物”之后应用的局部修正；`+` 为加法修正，`×` 为乘法修正。

### 木板墙 barricade

| 形态 | 定位 | Lv.2 | Lv.3 | 实现要点 |
|---|---|---|---|---|
| 铁壁 `ironwall` | 纯耐久 | `hp ×1.28` | `hp ×1.45` | 只提高最大生命，无攻击行为 |
| 尖刺反甲 `thornwall` | 反伤 | `hp ×1.08`，受击反伤 `8/s` | `hp ×1.18`，反伤 `14/s` | 复用 `retal`，在丧尸攻击建筑的同一帧结算 |
| 门闩 `gatewall` | 死亡控制 | `hp ×1.16`；死亡时本行减速 `35%/1.2s` | `hp ×1.30`；死亡时减速 `55%/1.6s` | `unitDead` 时对同侧行丧尸写入 `slowT/slowAmt` |

### 钉刺栅 spike

| 形态 | 定位 | Lv.2 | Lv.3 | 实现要点 |
|---|---|---|---|---|
| 放血齿 `bleedteeth` | 极限输出 | `hp ×0.90`，反伤 `×1.45` | `hp ×0.95`，反伤 `×1.70` | 反伤倍率最后乘，和 `fuse` 遗物相乘 |
| 钩镰刺 `hookspikes` | 控制 | 反伤 `×0.90`；丧尸攻击时 `18%` 概率眩晕 `0.5s` | 反伤 `×1.00`；概率 `28%`、眩晕 `0.7s` | 只在丧尸攻击事件触发，不能按每帧反伤重复判定 |
| 磷火刺 `phosphorspikes` | 持续伤害 | 反伤 `×1.00`；附加灼烧 `3/s, 1.5s` | 反伤 `×1.10`；灼烧 `5/s, 2.0s` | 给丧尸增加 `burnDps/burnT`，每帧扣血并发出一次死亡事件 |

### 弩炮 turret

| 形态 | 定位 | Lv.2 | Lv.3 | 实现要点 |
|---|---|---|---|---|
| 破甲弩 `armorpiercing` | 单体爆发 | `dmg ×1.45`，攻速 `×0.85` | `dmg ×1.65`，攻速 `×0.82` | 提高单发质量，降低攻速 |
| 连发弩 `rapidbow` | 持续输出 | `dmg ×0.82`，攻速 `×1.32` | `dmg ×0.88`，攻速 `×1.45` | 不额外生成箭，避免和“双管弩机”遗物重复 |
| 追迹弩 `trackerbow` | 远程暴击 | `range +90`，`dmg ×0.95`，暴击 `18%/×1.8` | `range +130`，`dmg ×1.00`，暴击 `28%/×1.8` | 在 `updateShots` 命中时判定暴击，弹道仍为单发 |

### 探照灯 lamp

| 形态 | 定位 | Lv.2 | Lv.3 | 实现要点 |
|---|---|---|---|---|
| 广域冷光 `widebeam` | 范围减速 | `radius +70`，`slow +0.10`，`dmg ×0.80` | `radius +110`，`slow +0.16`，`dmg ×0.85` | 减速上限仍为 `0.75` |
| 钠焰灯 `sodiumflare` | 范围灼烧 | `dmg ×1.55`，`slow ×0.70`，`radius -35` | `dmg ×1.80`，`slow ×0.75`，`radius -45` | 伤害提高但控制减弱 |
| 频闪灯 `stroboscope` | 控制 | `dmg ×1.05`，`slow ×0.90`，命中 `18%` 眩晕 `0.35s` | `dmg ×1.15`，`slow ×0.90`，概率 `28%`、眩晕 `0.50s` | 眩晕只在光束命中事件判定，不能每帧连续刷新 |

### 燃油喷口 flame

| 形态 | 定位 | Lv.2 | Lv.3 | 实现要点 |
|---|---|---|---|---|
| 扇面火 `fanfire` | 横向清场 | `spray ×1.50`，`range +15`，`dmg ×0.78` | `spray ×1.80`，`range +25`，`dmg ×0.82` | 扩大喷射宽度，降低单点伤害 |
| 聚焰火 `needlefire` | 线性爆发 | `dmg ×1.50`，`spray ×0.70`，`range +10` | `dmg ×1.75`，`spray ×0.65`，`range +15` | 收窄火焰，强化正前方目标 |
| 余烬火 `emberfire` | 灼烧续航 | 攻速 `×1.30`，`dmg ×0.90`；灼烧 `3/s, 1.2s` | 攻速 `×1.45`，`dmg ×0.95`；灼烧 `5/s, 1.6s` | 复用丧尸 `burnDps/burnT`，不改变喷火范围 |

### 电弧塔 tesla

| 形态 | 定位 | Lv.2 | Lv.3 | 实现要点 |
|---|---|---|---|---|
| 拓扑弧 `topology` | 多目标 | `chain +2`，`dmg ×0.78` | `chain +3`，`dmg ×0.82` | 连锁数先加后与遗物相加，最低为 `1` |
| 雷矛弧 `lightningspear` | 单体重击 | `dmg ×1.50`，`chain -1` | `dmg ×1.75`，`chain -1` | `chain` 下限 `1`，避免变成零目标 |
| 震荡弧 `pulsecoil` | 高频范围 | 攻速 `×1.30`，`radius +35`，`dmg ×0.85` | 攻速 `×1.45`，`radius +55`，`dmg ×0.90` | 不增加连锁数，靠频率和半径扩大覆盖 |

## 6. 数值与堆叠规则

- 等级成长保持现状：生命 `×1.35^(lv-1)`，伤害 `×1.42^(lv-1)`。
- 先计算基础值和等级成长，再乘全局遗物（`hpMul`、`dmgMul`、`rateMul`、`spikeMul`），最后应用形态局部修正。
- `chain`、`radius`、`range` 这类加法字段按“基础 + 遗物 + 形态”计算，并做下限/上限钳制。
- `slow` 最终钳制在 `[0, 0.75]`；`chain` 最终至少为 `1`。
- 形态不改变建筑基础造价，也不改变 `upgradeCost(type, lv)`；首次三选一仍只收一次 Lv.1→Lv.2 费用。
- 形态只在同一大局内存在；当前存档只保存排位信息，不需要额外持久化 `form`。
- 若 `lv >= 2` 但 `form` 缺失，使用 neutral 形态并保持现有战斗数值，避免异常构筑崩溃。

## 7. 代码接入点

### `js/config.js`

- 新增 `FORMS` 数据表和 `getForm(typeId, formId)`。
- 为每个形态提供 `lv2`、`lv3`、图标、定位和文案。
- 保留 `upgradeCost`、`unitHpAt`、`unitDmgAt`、`sellValue` 作为通用数值入口。

### `js/meta.js`

- `place` 创建 `form: null`。
- `upgradeAt` 在 `lv === 1 && !form` 时改为请求 UI 选择，不在扣费前升级。
- 新增 `beginFormChoice(col, lane)`、`confirmForm(formId)`、`cancelFormChoice()`。
- `confirmForm` 统一完成校验、扣费、`lv++`、`form` 写入和 `refreshBuild`。
- 回收逻辑不变，继续调用 `sellValue`。

### `js/ui.js`

- `syncUnitPanel` 对 Lv.1 建筑显示“首次升级 · 三选一”。
- 打开 `overlayMode='form'`，渲染三张固定顺序卡片。
- 卡片按钮通过事件委托调用 `Game.confirmForm`；取消按钮调用 `Game.cancelFormChoice`。
- `syncAll` 在 `overlayMode==='form'` 时不再被普通单位面板覆盖。

### `js/sim.js`

- `makeUnit` 接收 `form`，调用 `getForm` 后应用 `lv2/lv3` 局部修正。
- 增加反伤、眩晕、灼烧、暴击、死亡减速所需字段。
- 形态效果只在对应建筑类型分支内执行，避免给所有单位增加无用状态。

### `js/bots.js` 与 `tools/balance.js`

- 机器人首次升级时按小局种子和流派标签选择形态；同一 seed 必须得到同一形态。
- 平衡工具的玩家路径也要为 Lv.1→Lv.2 指定形态，至少覆盖每个形态各一次。
- 玩家面板显示形态名；镜像信息暂时只显示形态名，不展示完整数值。

## 8. 视觉与文案

- 选择框标题：`首次升级 · 三选一`
- 卡片结构：图标 / 形态名 / 定位标签 / Lv.2 效果 / Lv.3 预览 / 当前费用。
- 卡片底部固定显示“选择后不可在本小局更改”。
- 形态颜色只做辅助：耐久偏冷灰，反伤偏锈红，控制偏青白，爆发偏琥珀，电弧偏冰蓝。
- 战场不新增图片资源；Lv.2 起每个形态使用独立的程序化轮廓、材质、灯型或炮口造型，同时在单位面板显示形态名。

## 9. 验证与验收

实现后必须逐项验证：

1. 每个建筑首次升级都出现 3 张卡片，顺序固定。
2. 选择只扣一次 Lv.1→Lv.2 费用，`lv=2` 且 `form` 正确写入。
3. 取消选择后金币、等级、`form` 均不变。
4. Lv.2→Lv.3 不再出现形态选择，费用仍按现有公式计算。
5. 卖出带形态建筑的退款与升级前规则一致。
6. 形态字段能穿过 `Game.playerBuild`、`Battle.addUnit`、`makeUnit`。
7. 18 个形态在同seed下可重复得到相同机器人选择。
8. 遗物与形态的乘算/加算顺序符合第 6 节，慢速和连锁上下限不越界。
9. 运行 `node --check js/*.js` 和 `node tools/balance.js`，无语法错误、无模拟崩溃。
10. 以现有平衡结果为基线，逐形态跑平衡工具；任何单一形态都不得成为无条件最优解。

## 10. 实施状态

已按方案 A 完成运行时接入：

- `FORMS`、三选一状态机、战斗修正、镜像机器人和平衡工具均已接入。
- 18 个形态均有独立战场形象，并已验证任意形态都不会与基础形态或其他形态绘制相同。
- 备战期不再自动结束，顶部状态改为“准备中”，只有手动点击“开始防守”才进入战斗。
- 探照灯光锥朝向已修正；燃油喷口和弩炮仍保持各自原有朝向规则。
- 已通过 JS 语法、18 形态唯一性、升级/取消/确认/三级升级/回收、无倒计时、机器人确定性和形态战斗回归。
- 平衡工具已完成小规模全流程抽样并正常产出；默认参数是高次数全量采样，耗时较长，单独运行时需预留较长时间。
